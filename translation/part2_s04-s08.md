## §04 インストールする：入れてから、最初の一声まで

この節が終わる頃には、あなたのマシンの中に、会話できて仕事もできる Hermes が1ついるはずだ。以下の画面は、私が v0.22.2 で一画面ずつ実際に走らせて撮ったものだ。どのデフォルト値を変えた方がいいかは、その画面に来たところで言う。

### インストールの入り口を選ぶ

Hermes の入れ方は今3通りある。ターミナルに慣れているかどうかで選んでほしい。

| 入り口 | 向いている人 | 現状（v0.22.2） |
|---|---|---|
| デスクトップ版インストーラ | ターミナルに触りたくない人 | macOS と Windows にインストーラあり、Linux はなし。詳細は §19 の表を参照 |
| ワンライナースクリプト | ターミナルを開いてコマンドを1行打てる人 | macOS・Linux・WSL2 は `install.sh`、Windows ネイティブは PowerShell の `install.ps1` |
| Android の Termux | 古いスマホをサーバに使いたい人 | 公式署名付き APT リポジトリ。ドキュメントでは今もプレリリース扱い（§23） |

デスクトップ版は初回起動時にガイド対話が走る。あなたの名前、テーマカラー、つなぎたい App を聞いてくるもので、Nous が用意した一回限りの無料試用モデルを使うので、API キーは一切いらない。私はこのマシンには入れていない（本機にある既存の旧版 Hermes とデータディレクトリを共有してしまうので、そちらを触りたくなかった）。だからこの節はコマンドラインの道で進む。

コマンドラインの道について、公式が出しているのはこの1行だ。

```bash
# macOS / Linux / WSL2
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
```

```powershell
# Windows ネイティブ（PowerShell）
iex (irm https://hermes-agent.nousresearch.com/install.ps1)
```

入れたらターミナルウィンドウを開き直す（あるいは `source ~/.zshrc` する）。あとは `hermes` と打てば入れる。

先に、私自身がどう入れたかを言っておく。私はこの1行をそのままは実行していない。常用している `~/.hermes` に入ってしまうからだ。v0.22.2 のソースをクローンし、専用の仮想環境に入れて、`HERMES_HOME` でデータディレクトリをテスト用フォルダに向けた（この道の書き方は §23 にある）。入れ方は違うが、`hermes setup` 以降の画面はすべて同じものなので、以下の画面はそのまま照らし合わせてもらって大丈夫だ。

> **注意**
>
> ネット上の古いチュートリアルには `pip install hermes-agent` とか `brew install` と書いてあるものが多い。この2つの道は公式にはもうサポートされていない。PyPI のパッケージは 0.19.0 で止まっていて、それ以降のバージョンはインストールスクリプト、Docker、Nix でしか配られていない。pip で入れると 0.19.0 が入るので、後ろの章で話す Kanban ボードや `/learn` は手元に存在しないことになる。

スクリプトは依存関係を一式まとめて入れてくれる。Python 3.14、Node、ripgrep、FFmpeg。今はこれらを `hermes pm` というパッケージマネージャが管理していて、何か問題が起きたら `hermes pm doctor` を実行すれば何が欠けているか分かる。デフォルトでは、ヘッドレスブラウザ（Agent がネットに出るためのもの）と、コンピュータ操作ドライバ（Agent があなたのデスクトップを操作するためのもの）も入る。後者は当面使わないなら、インストール時に `--skip-computer-use` を付けると入らない。ブラウザの方は `--skip-browser` が対応する。

### セットアップウィザードを走らせる

初めて `hermes setup` を実行すると（新規インストールなら `hermes` と打つだけでも自動でここに入る）、まずこの画面が出る。

> 画面：まっさらな環境での `hermes setup` の最初の画面。三つの選択肢が並ぶ。

Quick Setup は Nous 自家製の Portal を通る道だ。ブラウザで一度クリックして認可すれば終わりで、モデルとツールが一括で設定される。Portal には無料枠があり、課金枠は月額20ドル、100ドル、200ドルの3段階（Plus、Super、Ultra）。ネット検索や画像生成といったツール Gateway 一式は課金枠側で、無料枠で使えるのは画像生成モデルの一部だけだ。長く使うつもりで、各プラットフォームに自分でキーを申請しに行くのが面倒なら、この道がいちばん楽だ。

Full setup は自分のキーを持ち込む道だ。中国の読者はおそらくこちらを選ぶだろう。手元にすでに DeepSeek、通義千問（Qwen）、Kimi、智譜（Zhipu）といったプラットフォームのキーがあるかもしれないからだ。今回の私もこの方法で配った。

Blank Slate は、ファイル、ターミナル、モデルだけを有効にして、あとは全部切る。「それぞれの能力が何をするものか理解してから一つずつ開けたい」という人や、社内向けに導入する場面に向いている。

### モデルを選ぶ

Full setup を選ぶと、最初にやるのはモデルをどこから持ってくるか選ぶことだ。このリスト、私が数えたところ全部で40の選択肢がある。

> 画面：プロバイダの選択。Nous Portal、OpenRouter、Anthropic、OpenAI（ChatGPT／Codex のサブスクリプションで直接ログインできる）、Qwen、Kimi、DeepSeek、Z.AI／GLM、MiniMax、StepFun、騰訊混元（Tencent Hunyuan）、小米 MiMo（Xiaomi MiMo）が並び、途中に「custom」（カスタム API）、一番下に「Local models」（ローカルモデル）がある。▸ が付いているものは第2階層のメニューがあるという印だ。

中国の各社も基本的に揃っている。▸ 付きの選択肢の下にはもう1階層ある。たとえば Qwen の下には Qwen Cloud、阿里雲百煉（Alibaba Cloud、中国リージョン）、Coding Plan、Token Plan といった複数に分かれていて、地域を選び間違えるとキーでエラーになる。私の手元にあるのは阿里雲百煉の中国リージョンのキーなので、「Alibaba Cloud DashScope (China)」を選んでキーを貼り付けた。入力中、画面にはアスタリスクしか表示されない。

続いてデフォルトのモデルを選ぶ。選んだプロバイダで使えるモデルが一覧で出てくる。

> 画面：阿里雲百煉の下のモデル一覧。`qwen3.8-max`、`qwen3.7-plus`、`kimi-k2.5`、`glm-5.2`、`deepseek-v4-pro`、`MiniMax-M2.5` などが直接選べるほか、モデル名を手入力することもできる。私が選んだのは `qwen3.7-plus`。

私が選んだのは `qwen3.7-plus` で、いちばん高い max ではない。理由は単純で、Agent は1ターンごとに大きな system prompt とツールの説明をモデルに送るので、トークン消費はチャットよりずっと大きい。日常的に回すなら中位のモデルで十分だ（実際にいくら燃えるかは、§07 の最後に今回の請求を出す）。次の画面では推論の強さを聞かれるが、私はデフォルトのまま触らなかった。

### ターミナルバックエンドを選ぶ

Agent にどこでコマンドを実行させるかを選ぶ。本機（デフォルト）、Docker／Podman コンテナ、Modal、SSH リモート、Daytona、Vercel Sandbox だ。

> 画面：ターミナルバックエンドの選択肢の一覧。

この画面は、Agent が打ったコマンドがどのマシンに落ちるかを決める。初めてなら本機でいい。他の選択肢をいつに換える価値があるかは §23 で話す。自分のパソコンでコマンドを走らせるのが特に不安なら Docker を選ぶ。コマンドは全部コンテナの中に閉じ込められる。

### チャットプラットフォームは飛ばす

次の画面にはチャットプラットフォームが長々と並ぶ。Telegram、Discord、Slack のほかに、微信（WeChat）、企業微信、飛書（Feishu／Lark）、釘釘（DingTalk）、QQ Bot、元宝（Yuanbao）もリストにある。初回のインストールでは何もチェックせず、そのまま Enter で飛ばしていい。コマンドラインで使い慣れてから、§08 で話すブラウザパネル側でつなげばいい。あちらには QR コードを読み取るだけで Telegram Bot を作れるような、もっと楽な入り口がある。

### Computer Use を切る

> 画面：コマンドライン版でデフォルトで有効になるツールの一覧。チェックが入っているのは、ネット検索、ブラウザ自動化、ターミナル、ファイルの読み書き、コード実行、画像を見ること、画像生成、音声、Skill、メモリ、セッション検索、サブ Agent への委任、定時タスク、そして後ろの方にある「Computer Use」（cua-driver 経由でデスクトップを背後で操作する）だ。

Computer Use がデフォルトで有効になっている点に注意してほしい。これは Agent があなたのデスクトップアプリを背後で操作できる、ということだ。能力は強いが、初めて入れる人には少し早い。私はここでスペースキーでチェックを外し、Enter で確定した。いずれ本当に必要になったら、`hermes setup tools` を実行してチェックを戻せばいい。

ブラウザツールを切らなかった場合は、続いてどのブラウザ方式を使うか聞かれる。

> 画面：ブラウザ方式の選択。ローカルのヘッドレス Chromium（推奨・無料）、Lightpanda、Nous サブスクリプションのクラウドブラウザ、Camofox、Browser Use、Browserbase、Firecrawl。

一番上の「Local Browser」でいい。無料で、キーもいらない。

### データを送るかどうかを選ぶ

> 画面：メトリクス共有の説明。数えるだけのデータ（活動、エラーの分類、トークンの総量、機能の利用状況）だけを集め、プロンプト、ファイル、パスは送らない、とある。選択肢は3つ。Nous に送る、本機だけで集める、集めない。「No thanks」がデフォルトで設定されている。

デフォルトは「集めない」だ。そのまま Enter でいい。

> 画面：ウィザードの終了画面。設定は `~/.hermes/config.yaml`、キーは `~/.hermes/.env` にあり、セッション、ログ、定時タスクもすべて `~/.hermes/` の下にある。下には、個別の部分だけを設定し直すコマンドが並ぶ。（私は隔離したディレクトリでテストしているので、画面のパスは `~` に短縮して表示されている。）

全部が `~/.hermes/` という1つのフォルダに入っている。引っ越しもバックアップも、このフォルダをコピーするだけだ。後からどこか1か所を変えたくなっても、全部をやり直す必要はない。`hermes setup model` はモデルだけ、`hermes setup tools` はツールだけを変更する。

### 自動で取り込まれたキーを確認する

この件はドキュメントでは見つけられなくて、ログをひっくり返して初めて気づいた。

初めてウィザードを走らせたとき、プロバイダの画面は OpenRouter がデフォルトで設定されていて、「currently active（現在有効）」とまで表示されていた。私はまだ何も設定していないのに、だ。後でログにこんな行を見つけた。

```
WARNING agent.credential_pool: Ingested OPENROUTER_API_KEY from environment
into the openrouter credential pool — this enables OpenRouter spend.
```

原因は、私のターミナル環境変数の中に、もともと `OPENROUTER_API_KEY` があったことだ（以前に別のツールで使ったもの）。Hermes は起動時に、環境の中にある認識できるキーを自動で自分の認証情報プールに取り込む。ログの中ではっきり言っている通り、これをすると「OpenRouter で課金が発生しうる」。

> **注意**
>
> あなたの `~/.zshrc` や `~/.bashrc` に OpenRouter、OpenAI、Anthropic などのキーを export したことがあるなら、Hermes はそれを自動で取り込む。必ずしも悪いことではないが、お金がそこから出ていく可能性があることは知っておくべきだ。使わせたくないなら、インストール前にその export の行をコメントアウトするか、インストール後に `hermes auth` で該当する認証情報を削除する。

### 初めて起動する

ウィザードが終わったら、`hermes` と打つ。

> 画面：起動画面。左側に現在のモデル（`qwen3.7-plus`）、作業ディレクトリ、セッション番号があり、下部に「21 tools · 58 skills」という集計がある。入力欄のグレイの文字はランダムに表示される例示のプロンプトだ。タイトルバーの日付はこのバージョンのビルド日。（テスト用ディレクトリのパスはマスクしてある。）

右側の欄には、ツールが種類別に（ブラウザ、ファイル、ターミナル、メモリ、委任……）、Skill が領域別に並んでいる。Apple のメモやリマインダーのような macOS 専属のものもあるし、Claude Code や Codex を呼び出せる Skill もある。他の Agent をどう指揮するかは、後ろの §15 で専門に話す。

ちゃんと設定できたか確認したければ、もう1つターミナルを開いて `hermes status` を実行する。

> 画面：`hermes status` の簡易出力。現在のモデル、プロバイダ、Gateway が動いているか、つながっているチャットプラットフォーム、定時タスクの数が分かる。全部見たい場合は `--full` を付ける。（この画面は §07 を終えた後に撮り直したものなので、定時タスクがすでに1つある。）

Gateway の項目は今は「stopped」になっている。これは正常だ。まだどのチャットプラットフォームにもつないでいないのだから。ただしこれは後で、定時タスクが自動で走れるかどうかに効いてくる。§07 で当たる。

>

## §05 初めての会話：覚えていく様子を見る

たった3文で、Hermes のメモリがどう働くかを自分の目で見られる。いつメモリに書くのか、どこに書くのか、閉じて開き直した後もあなたのことを覚えているのか。この節の各ステップは、そのまま真似してできる。

### 第一声：自己紹介と、ついでに仕事を1つ

私の最初の一言はこうだった。

> こんにちは！私は花叔です。コードは書けない独立開発者で、普段は中国語でやり取りします。
> 現在のディレクトリに todo.md を作って、今日のやることを3つ挙げてください：橙皮書を書く、動画を編集する、コメントに返信する。

この一文には実は2種類の情報が混ざっている。1つは私についての情報（名前、コードは書かない、中国語で話す）、もう1つはやらせる仕事だ。

> 画面：第1ターンの会話。Reasoning の枠の中で、まずユーザー情報を記録し、次にファイルを作る、と2つの仕事に自分で分解している。その後2つのツールがほぼ同時に実行された。🧠 memory が「User is 花叔……communicates in Chinese」という1文を書き込み、✍️ write が todo.md を作り、その下に diff が直接表示されている。`qwen3.7-plus`、v0.22.2。

ファイルを作る前に、Hermes はまず memory ツールを1回呼び出して、「私は誰か」を書き込んだ。覚えておけとは言っていない。長期的に残す価値のある事実だと自分で判断したのだ。

もう1つ小さいが大事な点がある。ファイルを書いた後、diff をターミナルの中に直接貼ってくれる。何行足されたかがその場で見えるので、別途ファイルを開いて確認しなくていい。

### 第二声：好みを1つ教える

続いて、私は注文を付けた。

> 今後、私にやることを挙げるときは、統一して「□」で始めてください。Markdown のチェックボックスは使わないで。
> あと、各項目の後ろに括弧で所要時間の見積もりを付けてください。

> 画面：第2ターン。まず todo.md を読み、`- [ ]` の3行を patch で「□ 橙皮書を書く (2h)」という形式に直した。返答では「今後、やることは □ で始めて、所要時間の見積もりを付けます」と言っている。

画面で見えるのは、ファイルを読んで直すところまでだ。「今後」という言葉を本当に覚えたのかどうかは、返答だけ見ても分からない。そこでメモリファイルを見に行った。

### メモリファイルを見る

メモリとは、Markdown ファイルが2つだけのものだ。`~/.hermes/memories/` の下にある。

> 画面：2ターンの会話の後のメモリファイル。USER.md には私についての1文、MEMORY.md には「やることの書式の好み：Markdown のチェックボックスの代わりに □ を使い、各項目の後ろに括弧で所要時間を書く」とある。2つのファイルの隣にある `.lock` は、書き込み時の同時競合を防ぐロックファイルだ。

2ターン目の好みも書き込まれていた。ツール呼び出しの数行は画面を流れていってしまったので、このターンで本当に memory を1回呼んだことは、ログ（`~/.hermes/logs/agent.log`）をひっくり返して確認した。

USER.md にはあなたについての事実を、MEMORY.md には好みと環境上のこだわりを記録する。どちらのファイルにも文字数の上限がある（MEMORY.md は約2200文字、USER.md は約1375文字）。いっぱいになれば、古いものを自分で消さなければならない。なぜこんなに細かく絞るのかは §12 で詳しく話す。

> **ポイント**
>
> この2つのファイルは、エディタで直接開いて直してかまわない。間違って覚えたもの、覚えてほしくないものがあれば、その行を消すだけだ。書き込む前に毎回確認させたいなら、設定の `memory.write_approval` を有効にする。そうすれば、メモリに書こうとするたびに確認がポップアップする。

### 閉じて、開き直す

`/exit` と入力して退出する。退出時には、今回のセッション番号と再開コマンドを教えてくれる。

> 画面：退出時のサマリー。`hermes --resume セッション番号` でも、`hermes -c "セッションタイトル"` でも続きを話せる。タイトルは Hermes 自身が付けたものだ。

ただし今回は続きを話さない。新しいセッションを開いて（もう一度 `hermes` と打って）、こう言った。

> 明日のやることも挙げてくれますか：動画を投稿する、週報を書く。ファイルは作らず、直接返信でいいです。

> 画面：まったく新しいセッションで、前の会話記録は何もない。Reasoning には「Looking at the memory, the todo list format preference is to use「□」……」とあり、出力は「□ 動画を投稿する（~30min）」「□ 週報を書く（~45min）」だった。

メモリファイルは起動のたびに注入される。だから最初から、□ を使うことと、時間を見積もることを知っていたわけだ。

正直に言うと、この体験はなかなか気に入っている。Claude Code を使うときも、私は似たような好みを CLAUDE.md に書く。でもあれは自分で書くものだ。ここでは、私が口で言っただけのことを、Hermes が自分で書き留めた。

### 2つの注意

第一に、何を覚えるかは Hermes 自身の判断で、毎回必ず覚える保証はない。私のこの2ターンでは、名前と「今後はいつも……」型の長期的な好みはどちらも記録された。本当に覚えさせたいことがあるなら、「覚えておいて：……」と直接言うのがいちばん確実だ。

第二に、メモリはモデルの目に触れるもので、毎回の回答に影響する。ある日、同じ件でいつも同じ間違いをしていると気づいたら、まずこの2つのファイルを見に行くといい。前に記録した古い情報が残っている可能性が高い。Hermes が「歪んで学ぶ」のをどう防ぐか、そして何を絶対に覚えるなと要求されているかは、§11 で専門に扱う。

## §06 一つの技を教える：/learn、Skill、そして Curator

メモリが管理するのは「あなたは誰か、何が好きか」で、Skill が管理するのは「ある仕事をどうやるか」だ。この節では週報を書くという小さな例で、教えるところから、どんな形で保存されるか、新しいセッションで自分から引っ張り出して使うところまでを、一通り歩く。

### コマンド1つで教える

以前は、Hermes に何かを覚えさせようと思ったら、複雑な仕事をやり終えた後に自分で総括してくれるのを期待するか（§09 で話すバックグラウンドの振り返り）、自分で SKILL.md を手書きするしかなかった。v0.18 以降、直通の道が1つ増えた。`/learn` だ。後ろに、覚えさせたいことを一文で続けるだけでいい。

私はこう教えた。

```
/learn 私は毎週金曜日に週報を書きます：~/demo の下の todo.md から今週完了したことを拾い、
「何をしたか／どこで詰まったか／来週何をするか」の3段で書き、各段は3行以内、口語で。
```

> 画面：`/learn` の最後の部分。`skill_manage` を呼び出して Skill を保存し、内蔵のチェッカーに license フィールドと作者名が欠けていると注意され、license を補った。最後の返答は「Skill saved: weekly-report-from-todo (category: productivity)」で、次に「週報を書いて」と言えばこれを使う、と伝えてくる。

Skill が保存された直後、Hermes 内蔵のチェッカーが警告を2つ出した。1つは license の欠落、もう1つは作者名だ。license の方は言われた通り直した。作者名の方は、チェッカーとシステムの規定が矛盾していると判断して直さなかった。その判断の過程は Reasoning の枠の中で見える。

### Skill はどんな形で保存されたか

Skill とはフォルダが1つで、`~/.hermes/skills/分類/Skill名/` の下に置かれる。核は1つの SKILL.md だ。

> 画面：`/learn` が生成した SKILL.md の冒頭。上は frontmatter（名前、一文の説明、バージョン、作者、license、タグ）、下は本文。いつ使うか、前提条件、どう実行するかで、その後にステップ、落とし穴、検証方法が続く（画面には全部は収まっていない）。

この形式は Claude Code や Codex の Skill と同じオープン標準（agentskills.io）に沿っている。だからこのファイルはそのまま他の Agent にコピーして使えるし、逆も同じだ。

このファイルを自分で読み終えて思ったのは、私のあの一文よりよほど周到に書けている、ということだ。たとえば、私が言っていない決まりを1つ補っていた。todo.md の中に完了したことが1つもなければ、その旨を正直に言い、でっち上げないこと。

`hermes skills list` を実行すると、すべての Skill が見える。

> 画面：`hermes skills list` の一部（私がフィルタしたもの）。Source の列で、内蔵のものは builtin、私が今教えた weekly-report-from-todo は local。最後の行の集計：Hub（コミュニティのマーケットプレイス）から入れたもの 0、内蔵 57、ローカル 1、合計58が有効。

その隣に、内蔵の weekly-review-planning という、名前のよく似た Skill があることにも注意してほしい。`/learn` のとき、Hermes は実はまずこの内蔵 Skill を見つけて読んだ。読んだ上で、これは週次レビュー方法論の一式であって、私の求める「1つのファイルから3段式の週報を生成する」ものとは別物だと判断し、新しく作ったのだ。

### セッションを換えて、自分で使うか見る

教えた後、私は退出して新しいセッションを開き、わざと言い方を変えた。

> 今週の週報を書いて

> 画面：新しいセッション。まず 📚 skill を呼び出して weekly-report-from-todo を読み込み、続いて todo.md を読んだ。Reasoning の中で、Skill に書かれたあの落とし穴を引用している。「If todo.md is empty or has no completed items, say so plainly rather than inventing content」。最後の返答は、今日のタスクはまだどれも完了していないので週報は生成できない、というものだった。「今週の計画」版を書くか、先に完了したことを補って入れるか、と聞いてきた。

私のテスト用 todo.md は、確かに3つとも未完了だった。Hermes は Skill のあの決まり通りに止まって私に聞き、週報を無理やりでっち上げたりはしなかった。

### /journey で、学んだものを見る

長く使うと、メモリと Skill をどれだけ溜めたのか知りたくなる。会話の中で `/journey` と入力する。

> 画面：`/journey` の出力。1本のタイムラインで、学んだ Skill（●）とメモリ（◆）に印が付いている。私のこのテスト機では Skill 1つ、メモリ2文で、どちらも同じ日付だ。日付は 19 Oct と表示されている。おそらく UTC で記録されていて、北京時間の未明はまだ UTC の前日にあたる。

入れたばかりの頃は点が数個しかなく、何も読み取れない。公式の説明によると、デスクトップ版には可視化されたメモリマップもあり、クリックして編集や削除ができるそうだ（私はデスクトップ版を入れていない）。

### Curator の状態を見る

Skill は溜まれば溜まるほど増える。一度使ったきり二度と使わないもの、互いに重なるものも出てくる。Hermes には Curator というバックグラウンドタスクがあり、専門にこの仕事をする。原理は §10 で詳しく話すので、ここでは状態だけ見ておく。

> 画面：`hermes curator status` の出力。初回実行は1周期後に先送りされている。今プレビューしたいなら `hermes curator run --dry-run` を実行できる。

この画面には、覚えておくべき数字が2つある。多くの古いチュートリアル（この本の前版を含む）の記述と違うからだ。アイドル状態が14日で期限切れ、30日でアーカイブ。前は30日と90日だった。そして、似た Skill の統合はデフォルトでオフ。今やっているのは、トークンを使わない剪定だけだ。統合も手伝わせたいなら、`curator.consolidate` を自分で有効にする必要がある。

> **ポイント**
>
> 命綱になるスイッチが2つ。ある Skill をアーカイブされたくないなら、`hermes curator pin Skill名` で固定する。アーカイブを間違えたら、`hermes curator restore Skill名` で戻す。変更のたびに `hermes curator ledger` に記録されていて、項目番号ごとに個別にロールバックできる（ライブラリ全体のスナップショットは、統合を有効にした後にだけできる）。デフォルトではアーカイブするだけで削除はしない。本当に消したいなら、自分で `hermes curator purge` を実行する。

## §07 あなたが眠っている間、何をしているか：定時タスクと Kanban ボード

ここまでの節は、あなたが一言言えば1つ動く、という形だった。この節では Hermes を自分で動かす。毎日決まった時刻に走るリマインダと、順番が決まっていて、1枚終われば自動で次に進むタスクカードの連なりだ。最後に、この一晩のテストのトークンの請求も全部表に出して見せる。

### 一言で定時タスクを作る

会話の中で、いつ何をしてほしいか直接言えばいい。cron 式を書く必要はない。

> 毎週の平日の朝9時に、~/demo/todo.md の中でまだ完了していないことを確認して、一言のリマインダにまとめてください。

> 画面：⏰ cron を呼び出して、「平日朝9時のやることリマインダ」というタスクを作った。返答には頻度、内容、次回実行時刻が並び、さらに2つのことを自ら注意してきた。Gateway が動いていないのでタスクは自動では発火しないこと、チャットプラットフォームにつないでいないので結果はローカルに保存されるだけだということ。

この2つの注意を、1つずつ話す。

第一に、定時タスクは Gateway に頼って走る。Hermes のスケジューラは gateway（メッセージ Gateway）プロセスの中にあり、Gateway が開いていなければ、タスクはリストに残るだけで発火しない。`hermes cron list` を実行すると、はっきり見える。

> 画面：`hermes cron list`。タスク番号、状態 active、スケジュール「weekdays at 9am」、無限に繰り返し、次回実行時刻、配信先は local。下には黄色の警告：Scheduler is not ready。この profile を担当する Gateway がなく、Gateway サービスをインストールするコマンドが表示されている。

Gateway を動かす方法は2つある。`hermes gateway run` はフォアグラウンドで走らせ、ターミナルを閉じれば止まる。`hermes gateway install` はシステムのバックグラウンドサービスとして入れる（macOS では launchd、Linux では systemd）ので、起動時に自動で上がる。本当に毎朝リマインドしてほしいなら後者を使う。私のテストでは前者のフォアグラウンドで走らせた。

> 画面：別のターミナルで `hermes gateway run` を走らせた後、`hermes cron status` は「Gateway is running — cron jobs will fire automatically」に変わり、次回実行は 09:00。下の Kanban ボードでは、第2のカードがすでに Gateway に自動で引き取られ、状態が running になっている（ボードについては後で話す）。

第二に、結果がどこへ届くかだ。チャットプラットフォームにつないでいない場合、結果はローカルファイルに保存される。明日の朝まで待たずに効果を見たければ、`hermes cron run タスク番号`、続いて `hermes cron tick` で、手動で1回走らせることができる。

> 画面：手動で1回発火させた後の出力ファイル。`~/.hermes/cron/output/タスク番号/` の下にあり、実行時刻で名前が付いている。一番下が今回の結果だ。「今日はまだ完了していないやることが3つあります：橙皮書を書く、動画を編集する、コメントに返信する。」

このファイルからは、私は途中のプロンプトの部分を削除した。その中では、Hermes があなたのタスクの前に、定時タスク専用のシステムプロンプトを一段付け加えている。そのうちの1条は「本当に報告する新しいことがなければ、[SILENT] とだけ返信すること」だ。これで、毎朝「今日は特に何もありません」という通知が届くことはなくなる。

> **ポイント**
>
> Telegram、微信、飛書といったプラットフォームをつないだ後は、そのチャットウィンドウで `/sethome` と送って、そこを「家」に設定する。以後、定時タスクの結果はデフォルトでここに送られる。このヒントは、実は初めて `hermes` を開いたときに一度ちらっと出ている（起動画面の下部の Tip だ）。

### Kanban ボードでタスクをつなぐ

定時タスクが管理するのは「いつやるか」で、Kanban ボード（看板）が管理するのは「順番のある数件の仕事を、どう引き継いでやり切るか」だ。たとえば私は3文版の週報がほしい。分解すると3ステップになる。まずやることを整理して優先順位を付け、次に週報の草稿を書き、最後に3文に圧縮する。後のステップは前のステップを待たなければならない。

まずコマンドラインでカードを3枚作る。後の2枚は `--parent` で前提タスクを指定する。

```bash
hermes kanban init
hermes kanban create "todo.md の今週のやることを整理し、優先順位順に並べる" --assignee default
hermes kanban create "並べたやることに基づいて週報の草稿を書く" --assignee default --parent <1枚目のカードの番号>
hermes kanban create "週報を3文に圧縮する" --assignee default --parent <2枚目のカードの番号>
```

> 画面：`hermes kanban list` と stats。1枚目のカードは ready（▶）、後の2枚は前提が終わっていないので todo（◻）に止まっている。

`--assignee default` は、デフォルトのこの Hermes に割り当てるという意味だ。profile は複数作れる（たとえばコードを書く専門のもの、調査専門のものに、それぞれ別のモデルを使わせる）。カードを誰に割り当てるかで、誰がその仕事をするかが決まる。

作り終えたら、やはり Gateway が動いている必要がある。Gateway の中にはスケジューラがあり、60秒ごとにボードを走査して、ready なカードを送り出す。待ちたくなければ、手動で `hermes kanban dispatch` を1周走らせることもできる。各カードは独立した worker プロセスを起動して仕事をし、終わるとサマリーを1段書く。

> 画面：`hermes kanban show` で1枚目のカードを見る。状態は done、開始から完了まで約37秒。Latest summary は worker が書いたサマリー（優先順位は、コメントに返信する＞橙皮書を書く＞動画を編集する、と並べた）。Runs には実行のたびの記録がある。カードはデフォルトで一時ワークスペースを使い、タスク完了後に削除される。

1枚目が終わると、2枚目は自動で todo から ready になり、Gateway に引き取られる。続いて3枚目だ。全体を通して、あなたが張り付いている必要はない。ブラウザパネル（§08）で見ると、こんな様子だ。

> 画面：ブラウザパネルの Kanban ページ。画面は簡体字中国語に切り替えてある。列は8つ。未分類、やること、ディスパッチ済み、ready、実行中、ブロック中、Review、完了。撮影した時点で、1枚目のカードは「完了」、2枚目は「ready」、3枚目は「やること」にあった。右上の「スケジューラを発火」は、手動の dispatch と同じだ。

Gateway を開けてから2分も経たないうちに、後の2枚のカードは引き継いで走り終えた（2枚目は 02:27 に完了、3枚目は 02:28 に完了、1枚あたり20〜30秒だ）。

> 画面：同じボード。3枚のカードがすべて「完了」に入った。カードを作ってから全部終わるまで、私はもう何も触っていない。Gateway を開けていただけだ。

2枚目のカードが書いた週報の草稿も、3枚目のカードが圧縮した3文も、worker はファイルに保存していた（weekly-report.md、weekly-report-3lines.md）。それぞれの一時ワークスペースの中だ。カードが完了すると同時に一時ワークスペースは片付けられ、ファイルも一緒に消えた。最後に私が回収できたのは、各カードのサマリーの1行と、「セッション」ページで worker の最後の返信をひっくり返して見つけたものだけだ。

1. 今週はまずコメントに返信する。優先順位が高く、見込み1時間。
2. 続いて橙皮書を書く。集中力が必要で、見込み2時間。
3. 最後に動画を編集する。柔軟に調整でき、見込み3時間。総工数は約6時間。

実は1枚目のカードの詳細の中で、すでに注意は出ていた（tip_scratch_workspace の行。「scratch workspaces are ephemeral」）。私が真に受けなかっただけだ。成果物を残したいなら、カードを作るときに `--workspace dir:/あなたの/ディレクトリ` を付けるか、カードの説明の中で worker に成果物を添付（artifacts）として提出するよう求める。そうすれば、片付ける前に Kanban の添付ストレージにコピーされる。

> **注意**
>
> Kanban のカードも定時タスクも、無人で走る。実行の過程で「同意」をクリックする人はそばにいない。こういう場面への Hermes のデフォルトのポリシーは、承認が必要な危険なコマンドに当たったら直接拒否する、というものだ。定時タスクは `approvals.cron_mode`、Kanban の worker のような単発の照会は `single_query_mode`、webhook の類は `unattended_mode` を見ていて、デフォルトはどれも deny だ。これは保護だが、同時に、「どこかのディレクトリを消す」「何かを公開する」といった不可逆な仕事を直接放り込むな、ということでもある。本当に任せたいなら、`--triage` でまず「未分類」に止めるか、終わったら Review に止めてあなたが一目見るようにする。

### トークン使用量を集計する

最後に、お金の話だ。`hermes insights` は直近30日の使用量を集計する。

> 画面：ここまで撮った時点の集計。セッション6つ、私が送ったメッセージは全部で9条だけ、ツール呼び出し27回、総トークン 522,576。プラットフォーム別では、コマンドラインの会話が35万、Kanban のカード1枚が15.9万、定時タスク1回が8.5千。Cost の欄は Unknown と出ている。`qwen3.7-plus` の価格表を持っていないからだ。

9条のメッセージで52万トークン。平均すると1条あたり5〜6万トークンになる。理由は、Agent は1ターンごとに system prompt、ツールの説明、メモリ、Skill の目録を一緒にモデルへ送り、1ターンの内側でも何度も往復するからだ（ファイルを読む、ファイルを変更する、それから返信する）。一番高いのは Kanban のカードだ。「優先順位を付ける」という小さいカード1枚で15.9万を食べた。worker は完全な Agent で、コンテキストを最初から読み込み直して仕事をするからだ。

トークンの大半は繰り返しのプロンプトキャッシュ部分で、キャッシュに対応したモデルならずっと安くなる（Hermes は設計上このキャッシュを守ることをとても大事にしていて、§12 で話す「凍結スナップショット」はそのためのものだ）。だが、この桁の感覚は持っておいてほしい。定時タスクは1回で走り切る小さな仕事に書くこと、Kanban のカードは細かく割りすぎないこと。1枚ごとの固定費はどれも安くない。

## §08 ブラウザパネル：1画面で全部を管理する

コマンドラインに慣れた後は、管理系の作業の多くはブラウザでクリックした方が速い。モデルを換える、チャットプラットフォームをつなぐ、MCP を入れる、定時タスクと Kanban を見る。この節ではパネルを一通り歩き、ついでにデスクトップ App とどういう関係かをはっきりさせる。

### 開く

```
hermes dashboard
```

デフォルトのアドレスは `http://127.0.0.1:9119` で、ブラウザは自動で開く（自動で開かせたくなければ `--no-open` を付ける）。初回は Web UI をビルドするのが先で、ターミナルには「Building web UI… installing workspace dependencies with npm ci」と表示される。私のマシンでは数分かかった。固まったと思わないでほしい。2回目以降は一瞬で開く。

> **注意**
>
> パネルは 127.0.0.1 にだけバインドされる。つまり、このマシンからしかアクセスできない。これは意図的なものだ。パネルの中では、あなたの API キーを見たり変えたりできる。スマホで見たいからといって LAN や公衆網に晒してはいけない。公式ドキュメントの言い方は、リモートアクセスは SSH トンネルか、認証付きのリバースプロキシを通すこと。以前あった認証を飛ばす `--insecure` パラメータは、今はもう効かない。

### まず画面を日本語に切り替える

左下に言語ボタンがあり、デフォルトは EN だ。開くと簡体字中国語、繁体字中国語、日本語など十数種類の言語から選べる。私は簡体字中国語に切り替えたので、以下の画面はすべて中国語の UI だ。正直に言うと、翻訳はまだ完全ではなく、サイドバーは半分が中国語で半分が英語、ページ内の説明文も英語のままのものが多い。ただ、よく使うボタンはだいたい訳されている。

> 画面：開いてデフォルトで表示されるのは「セッション」ページ。上部に総セッション数、アクティブ、アーカイブ、メッセージ数の統計があり、その下に最近のセッションが時系列で並ぶ。各行にはタイトル、モデル、メッセージ数、ソースがある。Kanban カードや cron タスクの実行もセッションとして数えられ、ソースに印が付く。

左のサイドバーは上から順に、対話、セッション、ファイル、モデル、ログ、定時タスク、Skill、プラグイン管理、MCP、チャットチャネル、Webhooks、ペアリング、マルチ Agent 設定、設定、シークレット、システム、ドキュメント、Kanban で、いちばん下には実績ページ（いろいろな機能を使うよう励ますための小さなゲームで、気にしなくていい）もある。

### 対話：ブラウザの中のターミナル

> 画面：「対話」ページ。右側でモデルや作業ディレクトリを切り替えたり、履歴セッションを見たりできる（ここでは前の節で私が作ったものが見える：todo の作成、明日のやることの列挙、週報の作成、定時タスク、Kanban カード）。

「対話」ページは、実はコマンドラインの UI をそのままブラウザに埋め込んだものだ。パネルの中の対話と、ターミナルで使うものは同じ一式で、ショートカットもスラッシュコマンドも同じ。だから前の節で覚えたことは全部そのまま使える。

### モデル：主モデルのほかに、あと2組ある

> 画面：「モデル」ページの設定エリア。主モデル（alibaba-cn · `qwen3.7-plus`、CHANGE をクリックして換える）、補助タスク（12項目、デフォルトは全部自動）、Mixture of Agents（複数のモデルが一緒に議論してから結論を出す組合せモデルで、デフォルトのプリセットは2つのモデルを参照している）。右側の説明：ローカルで集計したトークンには補助呼び出しと再試行が含まれず、請求とは合わないので、デフォルトでは費用は表示しない。

補助タスクという概念は、初めて見ると戸惑うかもしれない。主対話の外側にある、裏側の小さな仕事のことだ。コンテキストの圧縮、画像を見ること、Web ページの抽出、セッションにタイトルを付けること、スマート承認のときにコマンドが危険かどうかを判断すること、事後の振り返りで Skill を総括すること……全部で12項目ある。デフォルトは auto で、主モデルに従うか自動で選ぶ。主モデルが高い場合は、ここで補助タスクにだけ安いモデルを別途指定できて、かなり節約になる。

### 定時タスクと Skill

> 画面：「定時タスク」ページ。§07 で作った「平日朝9時のやることリマインダ」が表示され、スケジュールのルールと次回実行時刻が出ている。右側には一時停止、今すぐ実行、編集、削除のボタンがある。

> 画面：「Skill」ページ。左側は分類で絞り込み、右側は Skill の一覧で、各 Skill にスイッチがある。右上には「Learn a skill」（対話の中の `/learn` と同じ）と「New skill」（手で書く）がある。

Skill ページでいちばん実用的なのは、あのスイッチの並びだ。内蔵の50あまりの Skill は、どれも使うとは限らない。たとえば Apple のメモを使わないなら、それを切る。そうすれば、会話のたびにモデルへ送る Skill の目録が少し短くなる。

### MCP：公式に審査済みの接続が65個

> 画面：「MCP」ページ。上はインストール済み（私のところは0個）、下は Catalog（65）。公式に審査済みの MCP ディレクトリで、Airtable、Algolia、Amplitude、Asana……どれにも INSTALL ボタンがある。

この本の前版では、私は「公式ディレクトリには Linear と n8n の2つだけ」と書いた。4か月経って65個になった。入れるときは INSTALL をクリックし、ログイン認可が必要なものはブラウザが開いてログインを求めるので、自分で設定ファイルを直しに行く必要はない。§17 では MCP のもう1つの向きを話す。Hermes 自身を MCP サーバにして、他の Agent に使わせる方向だ。

### チャットチャネル：QR コード読み取りで Telegram Bot が作れる

> 画面：「CHANNELS」ページ。「0 of 32 channels configured」とあり、接続できるチャネルは全部で32個。上の方には Gateway が動いていないという表示がある。Telegram の欄には2つのつなぎ方がある。Quick Setup（推奨）は QR コードを読み取り、Telegram の中で確認すれば、Hermes が自動で Bot を作ってあなたのユーザー ID を識別する。もう1つは、自分で @BotFather に行って作ってから token を貼る方法だ。（私は隔離したディレクトリでテストしているので、画面のパスは `~/.hermes` に書き換えてある。）

以前 Telegram をつなぐには、まず @BotFather のところへ行って1ステップずつ Bot を作り、token をコピーし、自分のユーザー ID を調べて許可リストに書き込む必要があり、新人はだいたいどこかで詰まった。今は QR コードの道があり、体験の差はかなり大きい。

中国国内でよく使うものも揃っている。微信（WeChat）、企業微信、飛書（Feishu／Lark）、釘釘（DingTalk）、QQ Bot だ。ウィザードで見たあの画面も同じ顔ぶれだった。

> 画面：インストールウィザードの中のチャットプラットフォーム一覧（§04 で飛ばした画面）。Weixin／WeChat、QQ Bot、元宝（Yuanbao）、釘釘、飛書、企業微信、それに Telegram、Discord、Slack、WhatsApp、Signal、iMessage など。

つないだ後は、Gateway が動いていること（左下の「Gateway 状態」が「実行中」であること）を忘れないでほしい。そうでないとメッセージは届かない。

### シークレット：サブスクリプションでログインすれば、API キーが要るとは限らない

> 画面：「シークレット」ページのプロバイダログイン（OAuth）の部分。Nous Portal、ChatGPT または Codex のサブスクリプション、Qwen（Qwen CLI 経由）、MiniMax、xAI Grok（SuperGrok／Premium+）、GitHub Copilot、Anthropic のアカウント。各項目の横には対応するターミナルコマンドが書いてある。たとえば `hermes auth add openai-codex`。

このページはサブスクリプション利用者に特に役立つ。すでに ChatGPT Plus／Pro を払っているなら、サブスクリプションで直接ログインでき、別途 API の請求を開く必要はない。Anthropic の欄には、パネル上にかなり率直に書いてある。Claude のサブスクリプションでログインするには追加の使用クレジット（Extra Usage Credits）が必要で、Pro を開けばそのまま無料で使えるわけではない、と。

### システムページ：Portal と Curator の状態

> 画面：「システム」ページの一部。Nous Portal は未ログイン、推論は alibaba-cn を使っていると表示。その下は Tool Gateway のルーティングで、ネット検索、画像生成、動画生成、ブラウザといったツールは、Portal にログインすればその統合チャネルを通せるが、私はどれも設定していない。さらに下には Skill Curator の状態と「Run now」ボタンがある。

### デスクトップ App とはどういう関係か

デスクトップ App の話に戻る。これは独立した Electron アプリで、中のチャット UI、プロジェクト、Kanban、Connectors（チャットの中で Linear や Notion といった App を直接つなぐ）、Bot Mode（複数の bot に名前とアバターを付け、1つのグループに引っ張り込んで互いに会話させる）といったものは、ブラウザパネルより完全な一式だ。v0.22 では Simple と Advanced の2つのモードも加わり、Simple モードでは高度な設定が全部隠れる。

デスクトップ App とブラウザパネルの裏側にあるのは、同じ Hermes で、同じ `~/.hermes` ディレクトリだ。デスクトップ App で教えた Skill や、覚えたメモリは、コマンドラインでも同じように使える。逆も同じだ。だからどの入り口を選ぶかは、あなたの習慣で決めていい。

今回はテスト機にデスクトップ版を入れていない。上の記述は公式のリリース説明に沿って書いたもので、デスクトップ App の実際の画面のスクリーンショットは出せない。この点は先にはっきりさせておく。
